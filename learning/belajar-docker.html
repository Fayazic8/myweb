Docker & Kontainerisasi

Cara mengemas aplikasi supaya "jalan di laptop saya" berubah jadi "jalan di mana saja". Progres saat ini 40% — fondasi konsep sudah, tahap lanjut masih jalan.

01. Kenapa Docker? 02. Konsep Inti 03. Perintah Dasar 04. Dockerfile 05. Docker Compose ⚡ Cheatsheet

01.Kenapa Harus Docker?

Bayangkan Google Sheet dan App Script yang dipakai untuk sistem stok gorengan. Kalau itu dijalankan di server, dan servernya beda versi Node/Python dari laptop sendiri, bisa saja error yang tidak pernah muncul saat development. Docker menyelesaikan ini dengan cara membungkus aplikasi beserta seluruh dependensinya (library, runtime, config) jadi satu paket yang disebut container — sehingga perilakunya identik di mana pun dijalankan.

Analogi dapur: Dockerfile itu resep. Image itu adonan jadi yang sudah dicetak dan siap dipakai kapan saja. Container itu adonan yang sedang digoreng — hidup, jalan, bisa dimatikan dan dinyalakan lagi tanpa mengubah resepnya.

02.Konsep Inti

Image

Blueprint statis — berisi kode, dependensi, dan instruksi cara menjalankan aplikasi. Tidak berubah, hanya dibaca.

Container

Instance yang berjalan dari sebuah image. Bisa dinyalakan, dimatikan, dihapus, dibuat ulang kapan saja.

Dockerfile

File teks berisi langkah-langkah untuk membangun sebuah image, dari base image sampai perintah start.

Volume

Penyimpanan data yang tetap ada meski containernya dihapus — penting untuk data yang tidak boleh hilang.

Registry

Tempat menyimpan & mengambil image, contohnya Docker Hub — seperti GitHub tapi untuk image.

Network

Cara container saling terhubung, misalnya container aplikasi bicara ke container database.

03.Perintah Dasar yang Wajib Hafal

docker ps # lihat container yang sedang jalan
docker ps -a # lihat semua container termasuk yang mati
docker images # lihat semua image di lokal
docker run -d -p 8080:80 nginx # jalankan container dari image nginx
docker stop <container_id> # hentikan container
docker rm <container_id> # hapus container
docker rmi <image_id> # hapus image
docker logs <container_id> # lihat log output container
docker exec -it <container_id> bash # masuk ke dalam container

04.Dockerfile Sederhana

Contoh Dockerfile untuk aplikasi Node.js kecil — misal auto-responder atau bot yang pernah dicoba sebelumnya:

FROM node:20-alpine
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
EXPOSE 3000
CMD ["node", "index.js"]

Build dan jalankan:

docker build -t bot-wa .
docker run -d -p 3000:3000 --name bot-wa-running bot-wa

05.Docker Compose — Kelola Banyak Container

Kalau sistem terdiri dari lebih dari satu bagian (misal: bot + database), docker-compose.yml memudahkan menjalankan semuanya sekaligus dengan satu perintah.

version: "3.8"
services:
  bot:
    build: .
    ports:
      - "3000:3000"
    depends_on:
      - db
  db:
    image: postgres:16
    environment:
      POSTGRES_PASSWORD: contoh
docker compose up -d # jalankan semua service di background

⚡Cheatsheet Ringkas

  • Bersihkan sisa image/container nganggur: docker system prune -a
  • Cek pemakaian resource: docker stats
  • Copy file dari/ke container: docker cp file.txt <id>:/app/
  • Restart otomatis kalau server reboot: tambahkan restart: always di compose, atau --restart=always di docker run
Langkah lanjut: setelah paham konsep dasar ini, latihan paling efektif adalah container-kan salah satu proyek kecil yang sudah ada — misalnya sistem stok gorengan berbasis App Script tidak bisa, tapi kalau nanti bot WhatsApp dicoba ulang, itu kandidat bagus untuk di-dockerize.
